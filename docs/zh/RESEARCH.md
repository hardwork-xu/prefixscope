核心问题是：**精确前缀复用曲线能否同时避免为每个容量重新回放缓存，以及让排名存储随完整访问历史增长？**

## 已有工作与贡献边界

全部容量的 LRU 分析源自 [Mattson 等人（1970）](https://doi.org/10.1147/sj.92.0078)。PrefixScope 使用 [Fenwick（1994）](https://doi.org/10.1002/spe.4380240306) 描述的累积和数据结构。栈性质、前缀最大值、对数复杂度排名查询都不是本项目首次提出的。

[KVSET](https://arxiv.org/abs/2609.27746v1) 将栈距离分析用于 KV 缓存容量规划；其[固定版本实现](https://github.com/llc-kc/kv_cache_capacity_estimator/tree/a90dc298151a8e117aa37e3c30fc0686de5225fa) 已支持连续前缀指标。本项目是范围更窄的独立实现，不是 KVSET 生产实验的复现，也不是对其方法改名。仓库没有打包上游实现。

具体工程贡献是以下可审阅机制的组合：

1. 对时间戳 Fenwick 索引进行保序压缩，让结构存储随不同页数而非总访问次数增长；压缩可关闭以进行消融。
2. 使用按 token 加权的阈值直方图，在轨迹读完**之后**仍可任意选择容量，无需保存请求历史，也无需每次访问都更新全部容量。
3. 明确请求进入时的查询契约，提供独立有限缓存参考实现、严格输入验证、有边界的读取，以及关联版本的公开轨迹实验。

这些工程选择建立在已有技术之上。性能结论仅比较实际测量过的实现和负载。请求进入时查询的契约有助于审计，不被宣称为新的前缀命中算法。

## 模型与定义

模型是顺序完成的一系列请求。基准使用 **B = 16 tokens** 的完整块；API 允许其他正整数块大小，但同一个 profile 必须固定。每个页标识包含命名空间及前置前缀，同一请求内标识互不相同。

对请求 `i`，`n_i` 为完整输入 token 数，`p_i,1 ... p_i,m` 为 `m = floor(n_i / B)` 个完整页。不足一页的尾部计入分母，但不能复用。不插入生成输出；时间戳也不会触发并发调度。

令 `r_i,j` 为请求 `i` 到达前，该页在无限 LRU 栈中**从 1 开始**的排名；从未出现的页排名为无穷。查询全部排名后，才从左到右访问每个页，包括首个未命中页之后的页。

对容量 `C` 页，定义：

```math
q_{i,j} = \max_{1 \le k \le j} r_{i,k}, \qquad
L_i(C) = \sum_{j=1}^{m_i} \mathbf{1}[q_{i,j} \le C].
```

`L_i` 是最长连续可复用前缀，不是分别驻留的页数。遇到首个冷页后，后续阈值全部为无穷。对测量请求集合 `M`：

```math
H(q)=B\sum_{i\in M}\sum_j\mathbf{1}[q_{i,j}=q],\qquad
R(C)=\sum_{q\le C}H(q),\qquad
h(C)=\frac{R(C)}{\sum_{i\in M}n_i}.
```

实现约定分母为零时 `h(C)=0`。预热请求改变栈状态，但不计入直方图及 token 分母。目标高于最大可达命中率时返回 `None`；目标为零时返回零容量。只有外部提供适合该模型的固定每页字节数后，才能将页容量换算为字节；这不是 GPU 内存测量。

## 为什么在该模型内精确

**LRU 不变量。** 在每个请求边界，容量为 `C` 的有限 LRU 恰好包含无限栈前 `C` 页；若整个栈更小，则全部包含。两个实现都从空状态开始，并应用相同的从左至右访问序列，标准栈性质保证该不变量持续成立。

**前缀阈值。** 请求进入时，前 `j` 页全部驻留，当且仅当它们的排名都不超过 `C`，等价于 `q_i,j <= C`。这些指示量之和就是连续前缀长度。因此，直方图所得整数复用 token 数与独立有限回放完全一致。

**压缩不变量。** 每个已知页占用一个时间戳；Fenwick 前缀和给出不晚于该页的位置占用数，将其从已知页总数中扣除即可得到排名。当时间戳数组已满且有效位置不超过一半时，将有效时间戳排序并重新编号为 `1 ... U`，不会改变全序关系，所以保持全部排名及后续 LRU 行为。否则数组倍增，已有占用位置保持不变。

以上论证假定提供的页标识代表可互换的页，并忽略加密散列碰撞；它们不能证明与生产推理引擎一致。

## 复杂度与资源成本

令 `A` 为完整页总访问数，`U` 为不同页数，`K` 为查询容量数，`L` 为最大请求页数，`S0` 为初始槽位数（默认 **1024**）。以下采用通常的 word-RAM 与字典操作期望成本模型；任意原生标识字符串还需计入实际字节存储。

| 组成 | 时间 | 额外状态 |
|---|---|---|
| 排名查询／普通访问 | `O(log(U + S0))` | 共享压缩索引 |
| 一次压缩 | 排序与重建 `O(U log U + S)` | 临时 `O(U + S)` |
| 初始化及完整读取，摊还 | `O(S0 + A log(U + S0))` | `O(U + S0 + L)` |
| 直方图及任意容量曲线 | 每次曲线查询 `O(U log U + K log K + U + K)` | 临时 `O(U + K)` |
| 独立有限 LRU 基线 | 期望 `O(K A)` | `O(sum_k min(C_k, U))` |

压缩后至少空出一半数组供后续访问，因而排序和重建成本可摊还。倍增发生时已有超过旧数组一半的有效位置，因此 `S <= max(S0, 4U)`；未使用的零号元素另外计入。直方图键是至多为 `U` 的排名。`Profile` 不保留请求历史；`observe` 临时返回至多 `L` 个阈值。关闭压缩后，时间戳数组为 `O(A + S0)`。Python 字典、标识字符串、已加载的基准输入及输出对象都不包含在数组槽位指标中。

## 冻结假设与验收

[contract.json](../../experiments/contract.json) 在性能调优前写定，是目标的权威记录；目标不等于实测成果。

| 类型 | 实验前声明 |
|---|---|
| 速度目标 | 在 Qwen trace A、B 各自前 **2048** 条请求、**64** 个容量上，相对独立 `OrderedDict` 回放的分析时间中位数加速比均至少 **2.0×**。 |
| 存储目标 | `hot_loop_20000` 上，压缩 Fenwick 槽位数不超过未压缩版本的 **25%**；这是结构数组存储，不是进程 RSS。 |
| 正确性 | 整数复用 token 数完全相同，绝对误差 **0**；随机差分测试覆盖 **100** 个种子。 |
| 有条件的预期 | `K` 增长应有利于一次遍历排名分析；反复访问热点页应有利于压缩。单容量或大部分为冷页的负载可能更适合直接 LRU。 |

容量网格为 `64 + 256j` 页，`j=0...63`。辅助情况覆盖 256 或 2048 条请求以及 1、8、64 个容量。计时协议包含一次预热执行、五次重复、打乱实现执行顺序、单线程与 `perf_counter_ns`；计入新分析器创建、已归一化请求的全部分析和曲线构建，排除文件读取与归一化。独立新子进程的峰值 RSS 包含输入加载，并单独报告。这些是分析器测量，不是模型服务端到端延迟。实际结果应写入实验证据，包括退化场景与未达成目标。

## 数据有效性与外部有效性

[Qwen-Bailian 数据](https://github.com/alibaba-edu/qwen-bailian-usagetraces-anon/tree/5f7439c51ec248a0c585f7d90a41a6f57773b912) 是公开的生产来源匿名轨迹，不是模型或原始 token 文本语料。Apache-2.0 条款和上游归属另行保留。按文件原顺序选择前 `N` 条记录，仅将完整输入块与命名空间链接；输出长度、到达时间与不足块的 hash 不产生缓存条目。[上游 FAQ](https://github.com/alibaba-edu/qwen-bailian-usagetraces-anon/blob/5f7439c51ec248a0c585f7d90a41a6f57773b912/docs/qa-context-growth-pattern.md) 解释了尾部 padding 变化。合成压力轨迹单独标明。

[固定版本的 vLLM 设计](https://github.com/vllm-project/vllm/blob/379e9a1ea8a5995464d9bf775bcd36bb03a0995f/docs/design/prefix_caching.md) 包含固定页、引用计数、输出分配和逆序释放。PrefixScope 不建模这些机制，也不包含 TTL、准入决策、可变页大小、租户调度、多层传输与混合注意力状态。准确的生产容量规划需要在本版本之外进行引擎专属验证。轨迹子集和分析器加速不能证明生产吞吐提升、TTFT 改善或 GPU 内存节省。

后续值得研究的问题包括：引擎的驱逐语义会让曲线变化多少；插入生成输出怎样影响预算；当 `U` 本身过大时，有限历史的近似分析能否保留有用的误差保证。
