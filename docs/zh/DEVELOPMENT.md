## 决策与实现

我在比较当周 KVSET、H-Spec 和低比特蒸馏论文后，选择了前缀容量分析。实际主机是 Apple M1 Pro、16 GiB 内存；CPU 轨迹分析器可在这台机器上完成有意义的正确性和资源实验，而新建大模型训练流程难以获得同等验证。

初始目录没有项目文件或 Git 仓库，因此建立了独立仓库，没有修改全局 Git 身份。数值化实验协议先于核心实现提交。核心从数学不变量出发独立实现，未导入上游缓存分析器；已有 Mattson、Fenwick 和 KVSET 思路仍明确归属。

实现包含请求入口查询、前缀最大阈值直方图、时间戳压缩、独立 `OrderedDict` 回放、有界输入、链式散列和双语 CLI。单元测试同时覆盖压缩及不压缩路径，并在 100 个随机种子的轨迹上核对全部容量。完整基准随后运行预先定义的真实轨迹子集和不利合成场景。

## 实际遇到的问题

- 首次哈希锁生成没有包含 setuptools，因为 pip-tools 将它归为不会自动固定的 unsafe 包。使用 `--allow-unsafe` 重新生成后加入已验证的 setuptools 哈希。该选项控制依赖是否纳入，不关闭包哈希校验。
- 依赖元数据检查发现，当时最新 NumPy 2.5.3 和 contourpy 1.4.0 要求 Python 3.12。为保留声明的 Python 3.11 开发路径，明确固定 NumPy 2.2.6 和 contourpy 1.3.2，并重新执行哈希锁定安装。
- 严格类型检查发现 `argparse.error` 返回注解不符，以及 JSON 输入值收窄不足。CLI 改用 `NoReturn`，原生输入词元数在构造 `Request` 前先校验，保留核心断言。
- 源码检查与独立语义复核确认：请求内页唯一时，顺序更新排名的前缀最大值可能与入口快照相同。因此增加检查实际“先读后写”调用顺序的测试，没有错误地假设总命中数能识别该实现细节。
- 许可证检查将随仓库提供的 CFF schema 归属修正为 CC-BY-4.0，并保留原许可证。Qwen 数据继续采用 Apache-2.0；下载的原始轨迹不进入 Git。
- 本机没有 Docker、Podman 或 Colima，本机容器检查因此保留为 `not_run`；任何远端容器结果在发布证据中另行记录。

完整结果出现后，没有修改性能目标、容量网格、真实数据子集或删除有效测量。实测收益仅属于容量分析；少容量退化、真实子集没有压缩收益及计时波动均保留在结果中。
